# GPU (CUDA 12) stack for the benchmark run — any CUDA-12-capable NVIDIA card,
# Linux or WSL2. Verified on an RTX 3050.
#
#   pip install -r requirements-gpu.txt
#   pip install -e .        # optional; the launchers add src/ to PYTHONPATH
#   python -c "import jax; print(jax.default_backend(), jax.devices())"   # -> gpu [CudaDevice(id=0)]
#
# Python: 3.12, 3.13 and 3.14 all work. jax/jaxlib/jax-cuda12-plugin publish
# cp312/cp313/cp314 manylinux x86_64 wheels; the CUDA runtime ships inside the wheel,
# so only an NVIDIA driver new enough for CUDA 12 (>= 525) is needed, no system toolkit.
#
# Native Windows CANNOT use the GPU: jaxlib has a win_amd64 wheel but
# jax-cuda12-plugin is manylinux-only. Use WSL2. See docs/gpu_runbook.md.
#
# Versions below were verified together by the full test suite (205 tests).

jax[cuda12]==0.11.1
flax==0.12.9
optax==0.2.8
pillow

# cax==0.4.3 is deliberately NOT installed here. It was evaluated as an accelerator
# for the NCA rollout (see docs/cax_evaluation.md) and found to give no speedup on
# either CPU or GPU — both it and our jax.lax.scan core compile to the same XLA scan,
# and the CAX reference model in cax_eval.py is simply bigger (more channels, plus a
# Growing-NCA alive-mask the pipeline doesn't use). It was never on the pipeline's hot
# path; this just stops installing the dead weight for a real GPU run.
# `pip install cax==0.4.3` only if re-running `python -m pinca_jax.cax_eval` yourself
# — it degrades gracefully (prints "CAX path error" and skips) without it.

# Reference implementation for the migration-correctness gate only — never used in
# the benchmarks themselves, so the CPU build is the right one and saves ~3 GB of
# CUDA libraries that would duplicate what the jax wheel already ships:
#   pip install torch --index-url https://download.pytorch.org/whl/cpu
torch>=2.12,<3
